# にほちゃんマイク：場の話題を記録・発信する機能

更新: 2026-10-22

## 目的と二つのモード

にほちゃんマイクは次の二つの独立した用途を持つ。

1. **記事録音**: 運営者が明示的に開始・停止し、音声から記事の下書きを作る。既存の NIHOapp の機能。
2. **場の話題**: 同意と説明がある場で運営者が開始し、今話していることを短く記録する。v2 以降は選んだ内容をにほちゃん bot が会員フィードへ投稿する。

記事録音の音声を場の話題へ、場の話題の音声を記事へ、本人の新たな操作なしに流用しない。v3 の同一機器では記事録音を優先し、その間は場の話題を一時停止する。

狙いは、現地にいない人が場の様子を知って訪れたくなることと、後からその日の学びを振り返れること。録音や文字起こしを公開すること自体は狙いではない。

## v1: Mac だけで試す

- macOS 26 以上の Apple Silicon Mac で動く、手動起動の CLI を最初の製品形にする。常駐サービス、ログイン時自動起動、定期タスクは作らない。MacBook でも同じ公開リポジトリを取得・ビルドできるようにする。
- 入力機器を運営者が指定する。録音開始時と各区切りで機器 UID を照合し、切断や既定入力の切替時は止める。Mac 内蔵マイクへ黙って切り替えない。
- v1 は既定 2 分、最大 5 分の区切りで録音し、その都度 Apple SpeechAnalyzer / SpeechTranscriber で **Mac 内** 文字起こしする。手元の約33分の実音声では5分区切りの大半がプライバシー判定で見送られたため、短い区切りを既定にした。無音や短すぎる会話は見送る。現地で発話検知・無音後停止を評価する。区切り間の会話を取り落とさないことを優先する。
- 要約の既定は **Mac 内の AI**。Foundation Models を候補とし、実行前に利用可能性と日本語対応を確認する。利用できなければ明示的に失敗し、クラウドへ自動で送らない。将来の Haiku API は別 adapter とし、明示設定した場合だけ使う。Claude Code のサブスク認証を継続運転する第三者アプリの認証として流用しない。
- 各区切りで候補を判定する。条件を満たさない区切りは「見送り」にし、短文を強制生成しない。初期の成果物は Mac 内の日付別ログのみ。本文は日本語 140 文字以内（可視文字数）。時刻は別フィールド。
- 発言は伝聞として扱う。「西御門の谷戸は縄文時代からなんだって」のように会話の内容をにほちゃんの言葉で伝えてよい。歴史的事実の外部照合は必須にしない。ただし、話されていない細部や断定を足さず、話が不明瞭なら見送る。
- 人名、連絡先、個人を特定できる出来事、家庭、政治、宗教、健康、金銭、人間関係、未成年者の話などは本文に出さない。伏せ字化で安全とみなさず、話題全体を見送る。モデルへの指示に加え、出力の長さ・形式・危険語・重複をプログラムでも検査し、判断が曖昧なら見送る。
- 同じ話題の継続は、直近の採用済み要約を比較して見送る。新しい視点や具体的な学びが増えた場合だけ次の記録を作る。出力には生成時刻と対象音声の終了時刻を持つ。
- 音声は作成から **72 時間**、生の文字起こしは **168 時間**保持し、期限が来たら自動削除する。研究段階で振り返るための期間であり、保存先は Mac 内のアプリ専用ディレクトリ（ディレクトリ 0700、ファイル 0600）とする。Git、GitHub Actions、クラウドへ入れない。短文ログは研究結果として残し、明示削除できるようにする。
- 処理が落ちても保存済み区切りを重複生成しない。開始・停止・機器切断・モデル不足・空録音・変換失敗を区別して状態を示す。ログには本文、音声、文字起こしを混ぜない。

### v1 の操作と受入

- `doctor`: OS、SpeechTranscriber、日本語モデル、Mac 内 AI、入力機器、保存先を確認する。モデルの取得は別の明示操作にする。
- `inputs`: 入力機器の ID と表示名を列挙する。
- `run --input <ID>`: 指定した機器だけで録音を開始し、Ctrl-C で安全に止める。手動で録音中かが分かる表示を出す。v1 には停止・再開が確実にできることが必要。
- `once --audio <file>`: 同意を得た録音を 1 本処理し、現地 MacBook の最初の疎通に使う。プライベートな成果物は同じ保存先へ置く。
- 合成音声と合成文字起こしだけを公開 CI で使う。現地の実会話はリポジトリと CI に入れない。

## v2: 会員フィードへの投稿

- v1 の安全な短文を投稿候補として NIHOapp へ渡す。最初は運営者の承認後にのみ、NIHO 鎌倉の**会員フィード**へ投稿する。投稿間隔は会話の区切りから独立し、同一話題や変化の少ない区切りは省略する。
- NIHO ログイン中の運営者の Desktop で開始・停止・ミュートをいつでも操作できるようにする。機器の入力状態と公開状態を別々に表示する。現地参加者へは施設案内時に録音目的を対面で説明する運用を前提とする。
- bot は個人のアクセストークンや機器トークンで既存の投稿 API を直接呼ばず、拠点・操作権限・公開範囲・重複キーを検証する専用の受け口を使う。最初は `SPOT_MEMBERS` 限定。自動投稿や一般公開は、承認運用での誤投稿率と現地の反応を評価した後の段階。
- 投稿は拠点のデータとして保存し、削除・訂正・通報・拠点 purge の既存契約に従う。音声や生文字起こしは投稿に添付しない。
- 来訪前の人に見せる目的には、会員フィードとは別に公開ページ向け候補の選定が必要。v2 の最初の公開範囲を会員に限定する判断とは区別する。

## v3: 実機の入力へ切替

- 記事録音と場の話題を機器上で区別し、同時録音しない。記事録音が始まると場の話題を一時停止し、終了後も運営者の操作なしに再開しない。
- 場の話題の音声入力を BLE マイクから実機 adapter へ切り替える。転送先と認証は別途設計する。既存の「記事録音→NIHO API」の経路をそのまま場の話題へ流用しない。
- 表示灯は録音・ミュート・接続不良を区別する。物理的な停止方法と、Desktop 側の停止・ミュートを一致させる。

## 評価の観点

現地で同意を得た複数回のセッションを使い、発話の取りこぼし、文字起こしの内容、話題の有用性、重複、個人情報やセンシティブな話題の誤採用、会話終了から短文までの時間、BLE 切断時の振る舞いを人が確認する。v2 の自動公開を許す基準はこの結果を見て定める。

## リポジトリ境界

この公開リポジトリには v1 の汎用コード、設計、合成 fixture だけを置く。実音声、生文字起こし、ローカル短文ログ、認証情報、施設の運用鍵は置かない。公開 CI は標準 GitHub-hosted runner のみを使い、実マイク、Apple の日本語モデル、本人の AI アカウントを要求しない。

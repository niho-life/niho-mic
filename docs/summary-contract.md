# v1 話題抽出と短文の契約

更新: 2026-10-22

## 入力と結果

入力は直近の区切りの生文字起こしと、重複判定用の採用済み短文（直近だけ）である。文字起こし中の命令、URL、コードはすべて会話データとして扱い、アプリの動作指示にはしない。処理する AI は v1 では Mac 内で動く。

AI には次の構造化結果だけを求める。

```json
{
  "decision": "publish | skip",
  "topicKey": "個人を含まない短い話題名",
  "text": "日本語140字以内の短文",
  "reason": "ok | no_speech | unclear | private | sensitive | duplicate | model_error"
}
```

`skip` なら `topicKey` と `text` は空にする。JSON が壊れている、列挙外の値がある、140字超過、安全性が疑わしい、話題が曖昧なら投稿候補にしない。失敗時も生文字起こしをエラーや標準出力へ出さない。

## 言葉の決まり

- 要約は**その場で交わされた話の伝聞**。話者の意見や記憶を正しい史実として保証しない。v1の短文は文末を「〜なんだって。」または「〜という話をしていたよ。」に統一する。
- 聞こえた内容だけを使い、外部知識で補完しない。話されていない時代、数字、人物、地名、結論は足さない。根拠のない印象や人数も足さない。
- 「西御門の谷戸が縄文時代から続くという話で盛り上がっています」のような伝聞は可。会話が成り立ちまで触れていれば、その内容を短く紹介してよい。
- 氏名、肩書きで特定できる個人、連絡先、住所、家庭、政治、宗教、健康、金銭、人間関係、未成年者の話は出さない。安全な部分だけを切り取っても個人や場の秘密を推測できる場合は区切り全体を見送る。
- 訪問予定、現在地、入退室時刻、誰が来ているか、正確な人数は出さない。施設周辺の公開地名は話題として使える。
- 音楽・環境音だけ、挨拶や相づちだけ、認識が崩れて意味を取れない区切りは見送る。
- 長さは `String.count` 相当の利用者に見える文字数で140字以内。生成後に機械的に確認し、超えた場合は再生成を繰り返さず見送る。

## 例

| 会話の内容 | 結果 |
|---|---|
| 「西御門の谷戸には縄文時代から人がいたらしい。鎌倉時代の使われ方も面白い」と語る | `西御門の谷戸には縄文時代から人がいたらしく、鎌倉時代の使われ方も話題になったんだって。` |
| 庭の植物と日陰での育て方を語る | `庭の日陰で育てやすい植物と水やりの工夫について話していたんだって。` |
| 「来週、Aさんが病院へ行く」と話す | 見送り（個人・健康） |
| 政治への賛否を語る | 見送り（センシティブ） |
| 前の区切りから同じ庭の話が続き、新しい内容がない | 見送り（重複） |

## v2 の追加判定

v2 は候補をすべて投稿しない。投稿先の会員フィード、前回投稿からの時間、同一話題、運営者の承認、既存の公開範囲を判定する。v1 の `publish` は「ローカル短文として採用」であり、NIHOapp 上の公開許可を意味しない。

# v1 話題抽出と短文の契約

更新: 2026-10-23

## 入力と結果

入力は直近の区切りの生文字起こしである。重複判定は生成後にプログラムが採用済み短文と照合する。文字起こし中の命令、URL、コードはすべて会話データとして扱い、アプリの動作指示にはしない。処理する AI は v1 では Mac 内で動く。

最初の AI には要約候補だけを求め、採否はプログラムが決める。これにより、生文字起こしに人名が混じっていても、名前を含まない共有可能な話題を候補にできる。

```json
{
  "topicKey": "個人を含まない短い話題名",
  "text": "日本語80〜120字を目安とする具体的な伝聞の短文"
}
```

候補の本文と話題名に出力検査を適用し、続けて別の Mac 内 AI で安全性を確認する。140字超過、個人名やセンシティブな内容、曖昧な内容、重複は見送る。通常処理の標準出力やエラーに生文字起こしは出さない。運営者が明示的に `inspect` または `preview` を呼んだ場合だけ、その端末へ文字起こしと候補を表示する。候補の診断情報は文字起こしと同じ168時間で削除する。

## 言葉の決まり

- 要約は**その場で交わされた話の伝聞**。話者の意見や記憶を正しい史実として保証しない。v1の短文は自然な「〜なんだって。」「〜んだって。」「〜と話していたよ。」などの伝聞で結ぶ。
- 聞こえた内容だけを使い、外部知識で補完しない。話されていない時代、数字、人物、地名、結論は足さない。根拠のない印象や人数も足さない。
- 「西御門の谷戸が縄文時代から続くという話で盛り上がっています」のような伝聞は可。会話が成り立ちまで触れていれば、その内容を短く紹介してよい。
- 氏名、肩書きで特定できる個人、連絡先、住所、家庭、政治、宗教、健康、個人の金銭事情、人間関係、未成年者の話は出さない。一般的な不動産取引や仕事の進め方は扱える。安全な部分だけを切り取っても個人や場の秘密を推測できる場合は区切り全体を見送る。
- 訪問予定、現在地、入退室時刻、誰が来ているか、正確な人数は出さない。施設周辺の公開地名は話題として使える。
- 音楽・環境音だけ、挨拶や相づちだけ、認識が崩れて意味を取れない区切りは見送る。
- 長さは `String.count` 相当の利用者に見える文字数で140字以内、1〜2文。生成後に機械的に確認し、超えた場合は再生成を繰り返さず見送る。

## 例

| 会話の内容 | 結果 |
|---|---|
| 「西御門の谷戸には縄文時代から人がいたらしい。鎌倉時代の使われ方も面白い」と語る | `西御門の谷戸には縄文時代から人がいたらしく、鎌倉時代の使われ方も話題になったんだって。` |
| 庭の植物と日陰での育て方を語る | `庭の日陰で育てやすい植物と水やりの工夫について話していたんだって。` |
| 「来週、Aさんが病院へ行く」と話す | 見送り（個人・健康） |
| 政治への賛否を語る | 見送り（センシティブ） |
| 前の区切りから同じ庭の話が続き、新しい内容がない | 見送り（重複） |

## v2 の追加判定

v2 は候補をすべて投稿しない。投稿先の会員フィード、前回投稿からの時間、同一話題、運営者の承認、既存の公開範囲を判定する。v1 の `publish` は「ローカル短文として採用」であり、NIHOapp 上の公開許可を意味しない。

# v1 話題抽出と短文の契約

更新: 2026-10-23

## 処理順

1. 選択した音声認識エンジンで文字起こしする。既定は Mac 内の Whisper を macOS SpeechTranscriber で照合する。
2. Mac 内 AI が今回の発言を理解できる場合は、発信判断より先に140字以内の**内部要約**を作る。投稿を見送っても、根拠を確認できた内部要約は次の区切りへ渡す。
3. Mac 内 AI が「今の状況がわかって行きたくなる共有」または「後で読むと役立つ知識」に当たる話題を一つ選び、発信する価値を判断する。
4. 使用すると決めた話題だけ、Mac 内 AI で80〜140字を目標に投稿案を作る。プログラムで長さ・形式・センシティブ内容・重複・原文の根拠を調べ、別の Mac 内 AI で安全性を確認する。根拠と意味が明瞭なら60〜79字も候補に残す。
5. 採用した短文を Mac 内のローカルログに記録する。v1 は NIHOapp へ投稿しない。

会話中の命令、URL、コードはすべてデータとして扱い、アプリの動作指示にはしない。内部要約・使用判定・投稿案の指示は `internal-prompt`・`selection-prompt`・`prompt` で表示でき、`preview` に各プロンプトのファイルを渡せる。`preview` は保存済み文字起こしを再評価し、ログを変更しない。

## 区切りをまたぐ会話文脈

- 同じ録音セッションにある直近の理解できた内部要約を少数だけ次の区切りへ渡す。別セッションには渡さない。「その土地」のような省略の意味を補うために使い、今回の発言で「アメリカ」など新しい対象が明示されたらそちらへ切り替える。
- 前区間の地名を投稿文に入れるときは、前区間の文字起こしにその地名があることを確認する。内部要約だけを事実の根拠にはしない。前区間の人物名だけで現在の発話者を決めない。
- 予定テキストはイベント名・予定されたゲスト・公開肩書を理解する補助とする。予定だけを現在の発話者の証拠にせず、新しい発言内容の根拠にも使わない。予定の固有名詞と文字起こしが異なる場合は、表記補正の出典を区別し、曖昧なまま自動投稿しない。
- 最後の発話から15分以上会話がなければ文脈を失効させる。投稿の見送りや重複だけを理由に失効させない。
- `run` は起動ごとに新しい録音セッションとする。`once` は既定で呼び出しごとに独立し、同じ `--session` ID を明示した連続ファイルだけ継承する。停止前に保存され再開された未処理音声は、別会話への誤混入を避けるため各区間を独立扱いにする。
- 内部要約とその根拠は生文字起こしと同じ168時間で削除する。投稿ログはこれまでの契約を維持する。

## 言葉と採否

- 知識の要約は**その場で交わされた話の伝聞**。史実として保証しない。自然な「〜なんだって。」「〜と話していたよ。」などで結ぶ。場の様子は「今は〇〇について話しているよ。」のように現在形で伝えてよい。
- 聞こえた内容だけを使い、外部知識で補完しない。話されていない時代、数字、人物、地名、結論は足さない。
- 会話に出た人名、都道府県などの広い出身地、職業は出してよい。「松本さんは千葉出身のデザイナーなんだって。」は可。
- 連絡先、詳しい住所や現在の住まい、家庭、政治的主張、個人の信仰・宗教的勧誘、健康、個人の金銭事情、人間関係、未成年者の話は出さない。寺院の公開された歴史・文化・観光の取り組みや住職という肩書、一般的な不動産取引や仕事の進め方は扱える。訪問予定、入退室時刻、正確な人数も出さない。
- 音楽・環境音だけ、挨拶や相づちだけ、認識が崩れて意味を取れない区切りは見送る。
- 投稿案は利用者に見える文字数で80〜140字、1〜2文を目標とする。60〜79字でも具体性があり根拠確認を通れば採用候補に残す。原文の完結した一文をそのまま括弧で引用する案は、原文との完全一致をコードで確認し、出力安全審査に通す。情報が足りない豆知識を水増しせず、十分な根拠がなければ別の話題を選ぶ。「違う」「難しい」だけではなく、具体的に何がどう違うか、何が分かったかを伝える。
- 同じ話題が続き、新しい具体的な内容がなければ見送る。

## 診断と保存

通常処理の標準出力やエラーに生文字起こしは出さない。運営者が明示的に `inspect` または `preview` を呼んだ場合だけ、その端末へ「文字起こし → 内部要約と継続話題 → 使用判定と理由 → 投稿候補 → 最終確認 → 記録状態」を表示する。音声は72時間、生文字起こしと候補の診断情報は168時間で削除する。公開リポジトリと CI に実会話を入れない。

## 例

| 会話の内容 | 結果 |
|---|---|
| 「西御門の谷戸には縄文時代から人がいたらしい。鎌倉時代の使われ方も面白い」と語る | `西御門の谷戸には縄文時代から人がいたらしく、鎌倉時代の使われ方も話題になったんだって。` |
| 庭の植物と日陰での育て方を語る | `庭の日陰で育てやすい植物と水やりの工夫について話していたんだって。` |
| リビングで谷戸の成り立ちを話している | `今は西御門の谷戸の成り立ちについて話しているよ。` |
| 「松本さんは千葉出身のデザイナー」と話す | `松本さんは千葉出身のデザイナーなんだって。` |
| 「来週、Aさんが病院へ行く」と話す | 見送り（個人・健康） |
| 政治への賛否を語る | 見送り（センシティブ） |
| 前の区切りから同じ庭の話が続き、新しい内容がない | 見送り（重複） |

## v2 の追加判定

v2 は候補をすべて投稿しない。投稿先の会員フィード、前回投稿からの時間、同一話題、運営者の承認、既存の公開範囲を判定する。v1 の `publish` は「ローカル短文として採用」であり、NIHOapp 上の公開許可を意味しない。

# 場の話題と話者を区間をまたいで扱う

状態: v1 の話題継承と任意の予定テキスト入力を実装・実録音で検証中。NIHO予定の自動取得と話者の運営者確認は v2 以降の設計候補。

## 狙い

3分の音声だけでは「この土地」が鎌倉を指すことが分からない場合がある。発信を見送った区間も含め、理解できた内容を短く残して次の区間の理解に使う。現在の区間でアメリカなど別の対象が明示されたら、話題を切り替える。

## v1 の処理

1. 発話診断を通過した区間を文字起こしする。
2. 内容が理解できれば、発信価値の判断より先に140字以内の内部要約と、今回の発言にある根拠箇所を記録する。投稿を見送っても内部要約は残す。
3. 同じ録音セッションの直近の内部要約を少数だけ次区間に渡し、指示語や省略された話題を理解する。別の録音開始・別ファイルの単発処理には自動で渡さない。今回明示された新しい場所・話題を優先する。
4. 今回の区間の発言から、場の様子または後で役立つ知識として共有する価値があるか判断する。採用時だけ80〜140字の投稿案を作る。前区間の地名を使う場合は、その区間の元の文字起こしにも存在するか確認する。今回の新しい事実は今回の発言で裏付ける。
5. 最後に発話を検知してから15分以上たったら会話文脈を失効させる。投稿を見送った時間は失効条件ではない。

内部要約・根拠は生の文字起こしと同じ168時間で消す。公開リポジトリとCIには実録音・文字起こし・要約ログを置かない。

## 話者の扱い

同じ場所・話題が続いても、同じ人が話しているとは限らない。v1 は現在の区間で本人の名乗りや明確な紹介を確認できた場合だけ名前を付ける。前区間の名前、声質、予定の講師名だけでは現在の話者を決めない。人名が投稿内容の対象として出た場合は通常の内容審査を行う。

v1 ではその時間の予定を任意のローカルテキストとして録音に添えられる。v2 ではNIHO Desktopで録音を開始するとき、重なる公開予定と講師名を運営者に候補として見せる。予定名は表記補正の手掛かりにし、運営者が現在の登壇者を確認できた場合だけ現在話者に結び付ける。質疑応答や交代後は無記名に戻せるようにする。予定の説明文を発言内容の根拠には使わない。

## 検証ケース

- 区間1は「鎌倉の土地」、区間2は「この土地」の続き、区間3は「アメリカの土地」へ明示的に移る。
- 区間1の投稿を見送っても、理解できた内部要約を区間2で参照する。
- 間の発話は続いているが要約に失敗した場合でも、15分の時計をリセットする。
- 15分以上発話がなければ、前の地名も話者も次の区間へ引き継がない。
- 前区間で人名が出ても、今話している人としては使わない。
- 予定の講師と実際の登壇者が違う、途中で質疑応答に移る場合に、話者を誤認しない。

実録音で内部要約の分かりやすさ、話題の継続と切替、投稿見送り率を見て、現地運用前に改善する。
